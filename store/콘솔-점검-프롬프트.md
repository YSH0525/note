# 플레이 콘솔 점검 프롬프트 (크롬 확장용)

Claude는 격리된 클라우드 컨테이너에서 돌기 때문에 브라우저로 플레이 콘솔에 들어갈 수 없다.
콘솔에서만 보이는 정보는 브라우저에서 동작하는 에이전트(크롬 확장)에게 대신 시킨다.

**아래 블록을 그대로 복사해 확장에 붙여넣는다.** 앱 이름·패키지·상황 세 줄만 바꾸면
다른 앱에도 그대로 쓸 수 있다.

---

## 1. 상태 점검 (읽기 전용)

```
너는 내 크롬 브라우저에서 구글 플레이 콘솔을 대신 확인하는 에이전트다.
나는 개발자 계정 소유자이고 이미 로그인돼 있다.

# 절대 규칙 (어기면 되돌릴 수 없다)
- 읽기만 한다. 아래 항목을 읽어서 보고하는 것이 전부다.
- 다음 버튼은 절대 누르지 않는다:
  게시 · 검토를 위해 전송 · 변경사항 취소 · 변경사항 삭제 · 저장 ·
  출시 중단 · 앱 보관처리 · 릴리스 삭제
- 어떤 입력란에도 타이핑하지 않는다. 토글·체크박스를 건드리지 않는다.
- 판단이 서지 않으면 진행하지 말고 나에게 물어본다.
- 각 항목마다 스크린샷을 한 장씩 남긴다.

# 대상
- 콘솔: https://play.google.com/console
- 앱 이름: 폴드8노트 - 폴더블 노트·다이어리
- 패키지: com.yoonquelabs.foldnote
- 상황: v1.0(versionCode 1)을 2026-08-13 프로덕션 트랙에 제출했다.
  6일이 지나도 스토어에 안 보이고, 거절 통지는 받은 게 없다.
  왜 안 나오는지 원인을 찾는 게 목적이다.

# 확인 항목 (순서대로)

## 1) 게시 개요 — 관리형 게시  ← 가장 중요
좌측 메뉴 "게시 개요"(Publishing overview).
- "관리형 게시"(Managed publishing)가 사용 설정됨 / 사용 중지됨 중 어느 쪽인가?
- "검토 중인 변경사항"과 "게시 준비 완료" 목록에 각각 무엇이 들어 있는가?
  항목 이름과 상태를 그대로 옮겨 적는다.
- 게시 준비 완료 쪽에 항목이 있으면 심사는 이미 끝났고 게시 버튼만 안 눌린
  상태다. 이때도 버튼을 누르지 말고 그 사실만 보고한다.

## 2) 정책 상태
"정책 및 프로그램 → 정책 상태"(Policy status).
- 경고·위반·거부 항목이 있는가? 있으면 제목, 사유, 날짜, 위반한 정책 이름을
  요약하지 말고 문구 그대로 옮긴다.
- 특히 사칭(Impersonation), 스토어 등록정보(Store listing),
  지적재산권(Intellectual property) 관련 항목이 있는지 확인한다.

## 3) 알림함
우측 상단 종 아이콘 또는 좌측 "받은편지함".
- 최근 2주 안에 온 메시지의 제목과 날짜를 전부 나열한다.
- 거절·경고·추가 정보 요청이 있으면 본문 전체를 옮긴다.

## 4) 프로덕션 릴리스 상태
"테스트 및 출시 → 프로덕션".
- 최신 릴리스의 상태 문구를 그대로 적는다
  (검토 중 / 게시됨 / 거부됨 / 초안 / 업데이트 대기 중 등).
- 버전이 1.0 (versionCode 1)이 맞는지 확인한다.
- "검토 중"이면 예상 완료 시점 안내 문구가 있는지 본다.

## 5) 앱 콘텐츠 · 배포 국가
- "정책 및 프로그램 → 앱 콘텐츠": "주의 필요" 항목이 하나라도 남아 있는가?
- "프로덕션 → 국가/지역": 배포 국가가 몇 개인가?
  0개면 심사와 무관하게 스토어에 안 뜬다.

## 6) 기본 스토어 등록정보
"성장 → 스토어 등록정보 → 기본 스토어 등록정보".
- 앱 이름을 글자 그대로 적는다.
- 간단한 설명·자세한 설명이 채워져 있는가?
- 아이콘·그래픽 이미지·스크린샷이 각각 몇 개 올라가 있는가?

# 보고 형식
아래 형식 그대로 채워서 답한다. 모르면 "확인 불가"라고 쓰고 추측하지 않는다.
메뉴 이름이 화면과 다르면 비슷한 이름을 찾아 들어가되, 어디를 봤는지 밝힌다.

1. 관리형 게시: (사용 설정됨 / 사용 중지됨)
   검토 중인 변경사항:
   게시 준비 완료:
2. 정책 상태: (이상 없음 / 아래 내용)
3. 알림 (최근 2주):
4. 프로덕션 릴리스 상태:
   버전:
5. 앱 콘텐츠 미완료 항목:
   배포 국가 수:
6. 앱 이름:
   설명 채워짐(O/X):  아이콘(n)  그래픽(n)  스크린샷(n)
```

## 2. 앱 이름 변경 (별도 지시가 있을 때만)

> **주의.** 등록정보를 고치면 심사가 다시 큐에 들어가 대기 시간이 초기화될 수 있다.
> 1번 점검에서 **이름 때문이라는 근거를 확인한 뒤에만** 쓴다.

```
플레이 콘솔에서 앱 이름 한 곳만 바꾼다. 그 외에는 아무것도 건드리지 않는다.

- 대상: com.yoonquelabs.foldnote
- 경로: 성장 → 스토어 등록정보 → 기본 스토어 등록정보 → 앱 이름
- 바꿀 값 (앞뒤 공백 없이 정확히):
    폴드노트 - 폴더블 노트·다이어리

절차
1. 현재 값을 먼저 그대로 보고한다.
2. 앱 이름 칸만 위 값으로 교체한다. 간단한 설명·자세한 설명·이미지는 손대지 않는다.
3. 저장을 누르기 전에 바뀐 화면을 보여주고 나에게 확인을 받는다.
4. 내가 "저장"이라고 답하면 그때 저장한다. 답하기 전에는 누르지 않는다.
5. 저장 후 "검토를 위해 전송" 같은 추가 확인이 뜨면 누르지 말고 문구를 그대로 알려준다.
```

바꾸고 나면 저장소 쪽도 같이 맞춰야 한다 (Claude가 처리).

- `tools/play-publish.mjs` 의 `CONFIG.listing.title`
- `store/스토어-등록-정보.md`

두 값이 콘솔과 어긋나면 다음 `--listing` 실행이 **사용자가 정한 이름을 덮어쓴다.**

## 왜 읽기 전용으로 묶어두나

콘솔의 파괴적 동작은 대부분 확인 대화상자 하나뿐이고 되돌릴 수 없다.

| 버튼 | 누르면 |
|------|--------|
| 변경사항 취소 | 검토 중이던 편집 내용이 사라진다 |
| 게시 | 관리형 게시를 켜 둔 의미가 없어진다 |
| 출시 중단 | 이미 게시된 앱이 스토어에서 내려간다 |
| 앱 보관처리 | 되돌리기가 매우 번거롭다 |

에이전트에게 "확인해 줘"라고만 시키면 막힌 화면을 만났을 때 스스로 눌러서
뚫으려 든다. **금지 목록을 프롬프트 맨 앞에 두는 이유다.**
